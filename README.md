# برگر باز — منوی فارسی و سامانه مدیریت محتوا

یک برنامه واقعی Hono + TypeScript برای Cloudflare Pages/Workers، با پایگاه داده D1 و ذخیره تصاویر R2. این پروژه فقط **منوی نمایشی** است؛ سبد خرید، ثبت سفارش، پرداخت و حساب مشتری ندارد.

## روش‌های سرو و سه قیمت مستقل

در «آیتم‌های منو ← ویرایش ← روش سرو و قیمت هر مدل»، سه روش **ساده، میکس پنیر، قارچ و پنیر** را مستقل فعال/غیرفعال و قیمت‌گذاری کنید.

- قیمت هر مدل مبلغ نهایی به تومان است، نه مبلغ افزوده. اعداد فارسی/انگلیسی پذیرفته می‌شوند. قیمت خالی `null` است و «قیمت درج نشده» نمایش داده می‌شود.
- با فعال بودن حداقل یک مدل، قیمت تکی در سایت نمایش داده نمی‌شود ولی در داده محفوظ می‌ماند. پس از غیرفعال کردن همه مدل‌ها، قیمت تکی دوباره استفاده می‌شود.
- انتخاب روش سرو روی کارت، صفحه جزئیات و پنجره جزئیات صرفاً نمایشی است؛ خرید و سفارش اضافه نشده است. کنترل‌ها با صفحه‌کلید قابل استفاده‌اند.
- ذخیره پیش‌نویس قیمت عمومی را تغییر نمی‌دهد. «ذخیره و انتشار» تغییرات را عمومی می‌کند. تنظیم «نمایش قیمت‌ها» قیمت روش‌ها را در HTML و API هم پنهان می‌کند.
- روش غیرفعال و قیمت آن در API عمومی ارائه نمی‌شود؛ مدیریت همچنان هر سه مدل را می‌بیند.
- داده: `servingOptions: [{id, name, enabled, price}]`، شناسه‌های ثابت `plain`, `mixed-cheese`, `mushroom-cheese` و اعتبارسنجی سمت سرور.
- migration جدید `0002_serving_options.sql` هر دو نسخه پیش‌نویس و منتشرشده را بدون حذف قیمت‌های قبلی ارتقا می‌دهد. برای نصب قبلی ابتدا `npm run db:migrate:local` اجرا کنید.
- ابتدا روش‌ها غیرفعال‌اند تا برای محصول تأییدنشده (مثلاً شیک) مدل پنیر/قارچ نمایش داده نشود. مدل‌های موردنظر هر آیتم را خودتان فعال کنید. هیچ قیمت واقعی حدس زده نشده است.
- حساب با نقش `admin` به همه بخش‌ها دسترسی دارد و حساب نمایشی محدود نیست. اطلاعات دسترسی خصوصی، جدا از سورس تحویل می‌شود؛ احراز هویت حذف نشده است.
- آزمون اختصاصی: بعد از `npm run test:api` و نصب Playwright، `node tests/serving.mjs` روی دیتابیس محلی آزمایشی اجرا شود.

## وضعیت تحویل

- منوی RTL با ۶ دسته و ۴۴ آیتم: ۱۲ برگر، ۷ چیکن برگر، ۱۰ ساندویچ، ۴ سیب زمینی، ۶ اسنک و ۵ شیک.
- نام‌ها و توضیحات ارائه‌شده حفظ شده‌اند. قیمت‌ها `null` هستند و توضیحات ارائه‌نشده خالی‌اند.
- برچسب‌های «ساده»، «پنیر ترکیبی»، «سس قارچ» در دسته ساندویچ نگهداری می‌شوند؛ در فرم دسته و محصول قابل ویرایش و تخصیص‌اند. برای تبدیل به محصول مستقل، از «آیتم جدید» با همان نام و دسته استفاده کنید و برچسب قبلی را از دسته حذف کنید.
- هویت تصویری براساس لوگو و تصاویر مرجع کاربر، فونت Vazirmatn محلی، رابط واکنش‌گرا، جستجو، دسته‌بندی چسبان و جزئیات فقط‌خواندنی با dialog بومی، Escape و بازگشت فوکوس.
- پنل مدیریت واقعی: ایجاد/ویرایش/کپی/حذف/انتشار/پنهان‌سازی، پیش‌نویس مستقل از نسخه منتشرشده، کنترل ترتیب، قیمت اختیاری، ترکیبات ساختاریافته، وضعیت موجود بودن و برچسب‌ها.
- مدیریت دسته، کتابخانه رسانه، تنظیمات برند، پیش‌نمایش خصوصی، خروجی JSON بدون داده‌های احراز هویت، تغییر رمز و خروج امن.
- احراز هویت و مجوز سمت سرور، نشست دیتابیسی، کنترل CSRF و Origin، محدودسازی ورود، اعتبارسنجی، SQL پارامتری و کنترل نسخه هنگام ویرایش هم‌زمان.
- ۳۰ آزمون API و ۲۱ بررسی مرورگر در محیط محلی با موفقیت اجرا شده‌اند؛ تست مرورگر شامل عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۴۴۰ پیکسل است.
- دیپلوی تولید انجام نشده است. شناسه D1 در پیکربندی، شناسه صرفاً محلی است و باید پیش از دیپلوی تعویض شود.

### محدودیت مهم تصاویر

شش تصویر مستقل برگر از تصاویر مرجع ارائه‌شده استخراج شده‌اند. این تصاویر با عنوان **نمایشی** مشخص شده‌اند و جای عکس اختصاصی محصول را نمی‌گیرند. کیفیت اصلی این برش‌ها حدود ۲۵۷×۱۲۷ است؛ افزایش مصنوعی اندازه، جزئیات واقعی ایجاد نمی‌کند. برای ۳۸ محصول دیگر عکس دقیق و تأییدشده در دسترس نبوده است؛ عمداً عکس تکراری یا ترکیبات ساختگی نسبت داده نشده و آن‌ها به‌شکل تایپوگرافیک نمایش داده می‌شوند. داشبورد تعداد تصاویر مفقود را نشان می‌دهد. عکس‌های اختصاصی را از مدیریت آپلود و جایگزین کنید. تولید تصویر هوش مصنوعی انجام نشده است.

چند دارایی تصویری نمایشی حاصل جستجوی تصویر نیز در سورس وجود دارند؛ منوی پیش‌فرض آن‌ها را به محصولات نسبت نمی‌دهد. منابع:

- `hero.webp`: https://www.pickpik.com/yummy-fresh-burger-french-fries-bacon-dinner-78931

## راه‌اندازی محلی

نیازمندی: Node.js 22.12+، npm؛ برای پیش‌نمایش Sandbox از PM2 استفاده می‌شود.

```bash
cd /home/user/webapp
npm ci
npm run setup:local
npm run build
pm2 start ecosystem.config.cjs
```

در رایانه شخصی و خارج از Sandbox می‌توانید پس از build از `npm run dev:sandbox` استفاده کنید. تنظیم `cwd` در `ecosystem.config.cjs` را با محل پروژه روی رایانه خود تطبیق دهید.

- منو: http://localhost:3000/
- مدیریت: http://localhost:3000/admin
- مستندات داده عمومی: http://localhost:3000/api/menu
- پیش‌نمایش موقت اینترنتی با ابزار GetServiceUrl روی پورت ۳۰۰۰ ساخته می‌شود؛ نشانی دائمی تولید نیست.

`setup:local` یک کلید تصادفی خصوصی `BOOTSTRAP_TOKEN` در `.dev.vars` تولید می‌کند، migration را اجرا می‌کند و داده اولیه را وارد می‌کند. اجرای مجدد seed محتوا را تکثیر یا ویرایش‌های موجود را بازنویسی نمی‌کند.

### ایجاد حساب مدیر

1. فایل خصوصی `.dev.vars` را در رایانه/محیط قابل اعتماد باز کنید.
2. وارد `/admin` شوید. اگر مدیر موجود نباشد، فرم ساخت اولین مدیر نمایش داده می‌شود.
3. مقدار `BOOTSTRAP_TOKEN`، ایمیل خود و رمز اختصاصی حداقل ۱۲ نویسه را وارد کنید.
4. پس از ساخت اولین حساب، endpoint راه‌اندازی قفل می‌شود. هیچ رمز پیش‌فرض یا رمز تولیدی در کد وجود ندارد.
5. فایل `.dev.vars` را عمومی نکنید و در Git قرار ندهید.

نشست‌ها ۸ ساعت اعتبار دارند. تغییر رمز همه نشست‌های کاربر را باطل می‌کند. کوکی نشست همیشه Secure و HttpOnly و SameSite=Strict است؛ برای اجرا از HTTPS استفاده کنید. مرورگرهای مدرن localhost را استثنای امن توسعه می‌دانند؛ اجرا روی IP شبکه با HTTP پشتیبانی نمی‌شود. هش رمز PBKDF2-SHA256 با salt تصادفی و ۱۰۰٬۰۰۰ تکرار Web Crypto است؛ محدودیت Web Crypto محیط Workers لحاظ شده است. برای محیط‌های حساس، بررسی مستقل امنیت و در صورت نیاز مهاجرت به فراهم‌کننده احراز هویت مدیریت‌شده توصیه می‌شود.

### رفتار ذخیره‌سازی محلی

D1 و R2 با شبیه‌ساز واقعی Wrangler روی دیسک در `.wrangler/state` ذخیره می‌شوند، نه در حافظه برنامه. داده با refresh مرورگر یا restart برنامه حفظ می‌شود. **حذف/بازسازی Sandbox یا حذف پوشه `.wrangler` می‌تواند این داده محلی را از بین ببرد.** داده محلی خودکار به Cloudflare تولید منتقل نمی‌شود. فایل‌های محلی، رازها و نشست‌ها داخل آرشیو عمومی سورس قرار نمی‌گیرند.

## راهنمای پنل

- **نمای کلی:** شمارنده‌ها و آخرین ویرایش‌ها از داده ذخیره‌شده؛ شمارنده منتشرشده تعداد آیتم‌های دارای نسخه منتشرشده را نشان می‌دهد. پنهان بودن دسته، آیتم‌های آن را از منوی عمومی حذف می‌کند.
- **آیتم‌ها:** ساخت، ویرایش، کپی، فیلتر، جابه‌جایی با کلیدهای بالا/پایین، پیش‌نمایش اطلاعات جاری فرم، ذخیره پیش‌نویس و انتشار. قیمت فارسی یا انگلیسی پذیرفته می‌شود؛ فیلد خالی به `null` تبدیل می‌شود.
- **ترتیب:** دکمه‌های بالا/پایین ترتیب آیتم‌های همان دسته را جابه‌جا می‌کنند و تغییر ترتیب را در نسخه منتشرشده نیز اعمال می‌کنند؛ سایر پیش‌نویس‌ها منتشر نمی‌شوند. برای ترتیب دلخواه از فیلد عددی فرم استفاده کنید.
- **دسته‌ها:** حذف دسته دارای محصولات ممنوع است. ابتدا همه محصولات در نسخه پیش‌نویس و منتشرشده را منتقل/حذف کنید.
- **پیش‌نویس:** تغییر نام، ترکیبات، قیمت یا تصویر با ذخیره پیش‌نویس سایت را تغییر نمی‌دهد. «ذخیره و انتشار» نسخه عمومی را به‌روز می‌کند. «پنهان» نسخه عمومی را حذف می‌کند اما داده مدیریت باقی می‌ماند.
- **رسانه:** تصویر با فرمت JPEG/PNG/WebP و حجم حداکثر ۵ مگابایت. مرورگر تصویر را به WebP با ضلع بلند حداکثر ۱۶۰۰ تبدیل می‌کند. سرور نیز نوع و امضای فایل و اندازه را بررسی می‌کند؛ SVG و فایل‌های اجرایی پذیرفته نمی‌شوند. تصویر جایگزین از فرم آیتم/دسته/تنظیمات انتخاب می‌شود. حذف تصویرِ استفاده‌شده در پیش‌نویس یا نسخه عمومی مسدود می‌شود.
- **متن جایگزین:** متن رسانه، متن پیشنهادی است؛ متن اختصاصی هر آیتم در فرم خود آن نگهداری می‌شود. تغییر متن رسانه، متن قبلاً ثبت‌شده محصول را بازنویسی نمی‌کند.
- **تنظیمات:** هویت برند، لوگو، تصویر و متن hero، دو رنگ اصلی، تماس، ساعات، نشانی، لینک‌ها و پانوشت. مقادیر خالی در سایت نمایش داده نمی‌شوند. پیوندهای اجتماعی هر خط به فرم `عنوان | https://example.com` هستند.
- **پیش‌نمایش ذخیره‌شده:** همه پیش‌نویس‌های ذخیره‌شده را در یک صفحه خصوصی نشان می‌دهد، نه فرم‌های ذخیره‌نشده.
- **تعارض ویرایش:** پاسخ 409 به معنی نسخه قدیمی فرم است؛ پیش از ذخیره مجدد صفحه را تازه‌سازی و تغییرات را مقایسه کنید.

## مسیرها

### عمومی
| مسیر | کاربرد |
|---|---|
| `/` و `/menu` | منو؛ `/menu` به `/` هدایت می‌شود |
| `/category/:slug` | صفحه مستقل یک دسته منتشرشده |
| `/item/:slug` | جزئیات مستقل آیتم منتشرشده |
| `/api/menu` | فقط دسته‌ها، محصولات و تنظیمات منتشرشده |
| `/api/items/:slug` | آیتم منتشرشده با دسته منتشرشده |
| `/media/:key` | تصویر R2؛ تصاویر بدون ارجاع منتشرشده نیازمند نشست مدیرند |
| `/static/*` | دارایی‌های عمومی محلی |

### مدیریت
| مسیر | کاربرد |
|---|---|
| `/admin` | پنل دارای احراز هویت سمت سرور |
| `/admin/login` | ورود یا ساخت اولین مدیر با کلید خصوصی |
| `/admin/preview` | پیش‌نمایش خصوصی پیش‌نویس‌ها |
| `POST /api/auth/setup` | ساخت یک‌باره اولین مدیر |
| `POST /api/auth/login` | ورود، با محدودسازی نرخ |
| `GET /api/admin/me` | ایمیل مدیر فعلی و CSRF token نشست |
| `POST /api/admin/logout` | ابطال نشست |
| `POST /api/admin/password` | تغییر رمز و ابطال همه نشست‌ها |
| `GET /api/admin/content` | داده مدیریت و رسانه‌ها |
| `POST /api/admin/content/:kind` | ساخت items یا categories |
| `PUT /api/admin/content/:kind/:id` | ویرایش items/categories/settings با version و action |
| `DELETE /api/admin/content/:kind/:id` | حذف مجاز با version |
| `POST /api/admin/reorder/:kind` | جابه‌جایی اتمیک دو آیتم/دسته با کنترل نسخه |
| `POST/PUT/DELETE /api/admin/media[/:id]` | آپلود، ویرایش متن جایگزین، حذف امن |
| `GET /api/admin/export` | JSON محتوای مدیریت، بدون مدیران/هش‌ها/نشست‌ها |

در درخواست‌های تغییردهنده مدیریت، Cookie معتبر، `Origin` برابر مبدأ سایت و `X-CSRF-Token` لازم است. JSON با ساختار `{data, action: 'draft'|'publish'|'hide', version}` ارسال می‌شود. Upload از multipart/form-data استفاده می‌کند. نسخه داده بعد از ذخیره افزایش می‌یابد.

## معماری و مدل داده

- `src/index.tsx`: مسیرهای Hono، API، احراز مجوز و رسانه.
- `src/security.ts`: hashing، session، CSRF، محدودسازی تلاش ورود.
- `src/data.ts`: اعتبارسنجی و جداسازی payload عمومی/مدیریت.
- `src/views.ts`: HTML سمت سرور با escape متن، آیکون‌های SVG و صفحات.
- `public/static`: CSS، JavaScript بدون framework سنگین، فونت و تصاویر.
- `migrations/0001_initial.sql`: طرح D1، ایندکس‌ها و روابط.
- `scripts/seed.mjs`: محتوای اصلی؛ تولید `seed.sql` تکرارپذیر.
- `scripts/init-local.mjs`: ساخت راز محلی بدون بازنویسی راز موجود.
- `tests`: آزمون‌های API و مرورگر.

جدول‌ها: `categories`, `items`, `settings`, `admins`, `sessions`, `rate_limits`, `media`.
دسته و آیتم دو snapshot JSON معتبر (`draft` و `published`) دارند. `published=NULL` یعنی محتوای پنهان. `version` برای کنترل هم‌زمانی، `slug` یکتا و `category_id` کلید خارجی محافظ حذف است. snapshot محصول شامل name/slug/categoryId/shortDescription/fullDescription/ingredients/price/currency/imageUrl/imageAlt/badges/preparationLabels/isAvailable/sortOrder/representativeImage است. آرایه‌ها و فیلدها در سرور اعتبارسنجی می‌شوند. تنظیمات یک ردیف با شناسه ۱ دارد. رسانه شامل نام، کلید R2، نوع، اندازه و alt است. شناسه نشست به‌صورت هش SHA-256 در D1 نگهداری می‌شود.

## آزمایش

فقط روی دیتابیس محلی جداگانه و بدون محتوای واقعی کاربر اجرا کنید. تست API حساب آزمایشی می‌سازد؛ رمز تصادفی در `artifacts/test-auth.json` خارج از Git قرار می‌گیرد. تست مرورگر از همان حساب استفاده می‌کند. در محیط از قبل دارای مدیر، حساب آزمایشی باید قبلاً ساخته شده باشد؛ تست برای دیتابیس تولید طراحی نشده است.

```bash
npm run test:api
npx playwright install --with-deps chromium
npm run test:browser
npx tsc --noEmit
npm audit
```

نتایج و تصاویر آزمون در `artifacts/` ذخیره می‌شوند. تست‌های محتوایی داده‌های آزمایشی ایجادشده را پاک می‌کنند. پس از آزمایش در محیط محلی، برای بازشدن فرم راه‌اندازی اولیه، حساب `qa-local@burgerbaz.test` را با دستور D1 محلی حذف کنید؛ هرگز این کار را روی دیتابیس تولید بدون بررسی انجام ندهید.

## آماده‌سازی دیپلوی بعدی روی حساب شخصی Cloudflare

**این مراحل در تحویل اجرا نشده‌اند.** در زمان تصمیم به دیپلوی، token حساب Cloudflare را در Deploy panel تنظیم کنید؛ آن را در فایل عمومی یا سورس وارد نکنید. برای GitHub یا محیط CI نیز secret جداگانه به‌کار ببرید. هیچ API خارجی AI یا پرداختی نیاز نیست.

1. D1 واقعی با نام `burgerbaz-menu` و bucket خصوصی R2 با نام `burgerbaz-media` بسازید؛ R2 ممکن است نیاز به فعال‌سازی حساب و تنظیم صورتحساب داشته باشد.
2. `database_id` واقعی را در `wrangler.jsonc` جایگزین شناسه محلی کنید. bindingها باید دقیقاً `DB` و `MEDIA` باشند.
3. migration را روی دیتابیس واقعی اعمال کنید؛ seed اصلی را فقط برای شروع داده وارد کنید:

```bash
npx wrangler d1 migrations apply burgerbaz-menu --remote
npx wrangler d1 execute burgerbaz-menu --remote --file=seed.sql
npm run build
```

4. پروژه Pages را در حساب خود بسازید و خروجی `dist` را با Wrangler منتشر کنید. نام پروژه واقعی را هنگام انتشار مشخص کنید. پس از انجام این کار، یک کلید تصادفی مستقل تولید و secret `BOOTSTRAP_TOKEN` را به محیط Production پروژه Pages اضافه کنید؛ مقدار `.dev.vars` محلی خودکار منتشر نمی‌شود.
5. bindingهای D1/R2 و secret باید قبل از استفاده برنامه در Production فعال باشند. پس از تغییر تنظیمات محیط، deployment جدید ایجاد کنید.
6. `/admin` را روی دامنه HTTPS باز کنید و حساب تولید خود را بسازید. حساب محلی به تولید منتقل نمی‌شود. پس از ساخت حساب می‌توانید secret راه‌اندازی را حذف و دوباره deploy کنید؛ ایجاد حساب دوم از این مسیر از ابتدا هم مسدود است.
7. تمام تست‌های مجوز، upload، دامنه و کوکی را روی محیط staging بررسی کنید. آزمون‌های مخرب local را روی تولید اجرا نکنید.
8. برای انتقال محتوای ویرایش‌شده محلی، خروجی امن و بررسی‌شده از D1 و فایل‌های R2 تهیه و جداگانه منتقل کنید؛ seed اصلی جایگزین migration محتوای فعلی نیست. نسخه کامل D1 ممکن است اطلاعات حساس مدیران داشته باشد و نباید عمومی شود.

متغیرهای لازم: فقط `BOOTSTRAP_TOKEN` برای ساخت اولین مدیر. bindingهای لازم: `DB` و `MEDIA`. هیچ token یا رمز تولیدی hardcode نشده است. هدر HTTPS کوکی به مبدأ درخواست بستگی دارد؛ پروکسی باید scheme و host واقعی را حفظ کند.

## موارد باقی‌مانده برای بهره‌برداری تجاری

- عکس‌های اختصاصی و باکیفیت ۴۴ محصول، به‌ویژه ۳۸ مورد بدون عکس؛ عکس‌های مرجع موجود نیز برای hero بزرگ کیفیت محدود دارند.
- اطلاعات واقعی تماس/ساعات، قیمت‌ها و توضیحات تکمیلی در صورت تمایل صاحب برند.
- ساخت منابع Cloudflare تولید، secret تولید، دامنه و سیاست backup منظم.
- بازبینی امنیت مستقل، آزمون ظرفیت روی پلن واقعی و ارزیابی دسترس‌پذیری با محتوای نهایی. هش رمز و تصاویر روی پلن رایگان ممکن است به محدودیت CPU بخورند؛ تست staging و پلن مناسب ضروری است.
- بازیابی رمز با ایمیل، MFA، مدیریت چند نقش، تاریخچه ممیزی و بازگردانی خودکار backup در این نسخه پیاده‌سازی نشده‌اند. یک مدیر اولیه و نشست‌های متعدد پشتیبانی می‌شوند.

## دریافت سورس و backup

فایل سورس شامل کد، migration، seed، تست‌ها و دارایی‌هاست. `node_modules`, `.wrangler`, `.dev.vars`, `artifacts` و اطلاعات ورود از آرشیو عمومی کنار گذاشته می‌شوند. پس از استخراج، `npm ci` و `npm run setup:local` را اجرا کنید. نشانی اینترنتی پیش‌نمایش در پیام تحویل ارائه می‌شود و تولید دائمی محسوب نمی‌شود.
